- **Targets and identities.** Reserve `projex_recovery_source_i26freiser01` for disposable synthetic source data and `projex_restore_verify_i26freiser01` for the initially empty restore. Propose distinct non-superuser, no-createdb, no-createrole, no-inherit, no-replication, no-bypass-RLS owners `projex_i26_source_user` and `projex_i26_restore_user`, each limited to its own target; revoke disposable-database access from `PUBLIC`. The restore name matches `buildPgRestorePlan`'s guard; the backup script has **no equivalent source-name, role, or loopback guard**, so a separately approved fail-closed source-identity check is required before execution. Do not change privileges on normal `projex` to make this plan work.
- **Filesystem targets.** Under one separately approved canonical isolated parent, reserve `i26freiser01/source-git`, `i26freiser01/paired-backups`, and `i26freiser01/restored-git`. Approve their absolute parent and owner before creation. Verify realpath/canonical spelling, permissions, empty destination and fresh backup ID, no link/junction/reparse traversal, and pairwise non-overlap with each other, the checkout, normal managed Git root, and standard test Git root. The source is a separate disposable managed root, **not** the standard `projex_git_test` root protected by `validateBackupPaths`. Existing repository markers identify bare repositories and the backup tool marks its own incomplete output; no dedicated recovery-root ownership sentinel exists. Add an approved ownership/emptiness guard before any extraction or cleanup.
- **Later backup sequence.** Provision only synthetic source records and a bare repository through guarded flows, then stop traffic/API/Java and Git workers so database and Git cannot change between captures. Require no RUNNING execution/provisioning jobs, no PROVISIONING repositories, and empty Git staging and transport-request directories. `operations-backup.ts` already requires `--execute` and an explicit confirmation, uses `validateBackupPaths`, fixed `pg_dump --format=custom --no-owner --no-privileges` and full-root `tar` plans, and creates artifact SHA-256 and a constrained manifest. Record the exact commit, committed migration list, safe user/Class/activity/submission/repository counts and storage states, marker/quarantine counts, and tool versions. Independently enforce the approved source identity and normal-Git-root exclusion before this script runs.
- **Later restore sequence.** Verify both artifact hashes and manifest checksum before touching an empty destination. `operations-restore-preflight.ts` already requires `RESTORE_VERIFY_DATABASE_URL`, checks the guarded name and path containment, and builds fixed `pg_restore --exit-on-error --single-transaction --no-owner --no-privileges` and `git fsck --full` plans; it does **not** execute them. A later approved guarded executor/operator procedure must prove connected database/role/loopback identity and emptiness, validate archive entries against escape/link hazards, extract only into the isolated empty Git root, and restore only into the named empty database. Compare migrations and safe counts; check representative academic/repository relationships, storage states, repository/provisioning-job markers, DB-record-to-bare-repository correspondence, zero orphans, and full fsck for each restored repository. Then check isolated loopback health/capabilities and synthetic authentication. `verifyRepositoryCorrespondence` and `buildRestoreEvidence` support parts of this verification, but no script orchestrates the complete proof.
- **Abort conditions.** Stop on unknown or normal database identity, unapproved/effectively overprivileged role, non-loopback target, missing/dirty destination, migration drift, changed or mismatched checksum, unsafe archive member, any root alias/canonical mismatch, path overlap or link/junction/reparse condition, running jobs or transitional Git data, repository/marker mismatch, orphan, fsck failure, or any step requiring replacement or cleanup of normal data. Never interpret a preflight `ready` result as permission to execute a restore.
- **Evidence and gates.** Retain only redacted target-identity/privilege/emptiness attestations, source commit and migration names, manifest and checksums, safe count/state comparisons, relationship/marker/orphan/fsck results, and health/auth outcomes. Do not record URLs, credentials, private paths, source, hidden tests, or personal data. Creating roles/databases/roots, migrating the synthetic source, provisioning data, dumping/archiving, extracting, running `pg_restore`, cleanup, service changes, and any normal-data operation each require their applicable separate approval. This planning slice performs none of them.
